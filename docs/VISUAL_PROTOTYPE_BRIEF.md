# Gate 2.25 — Visual Prototype Brief

## Objective

Produce **2–3 coherent full-screen prototypes** for the selected `Freight Ledger` direction before writing product UI code.

The prototypes must test composition and information hierarchy, not just color styling.

## Non-negotiable content

Every prototype must show the same frozen product state:

- prioritized shipment manifest;
- one selected shipment;
- visible Exposure Index;
- top reason codes;
- central Risk Corridor;
- at least one peak exposure/dwell interval;
- factor-contribution explanation;
- public-context reference labelled as aggregate context;
- human-review action area;
- synthetic-data indicator.

The prototypes should use the same content so the comparison is about design, not different stories.

## Suggested hero scenario

Use a synthetic shipment with:
- very-high cargo value;
- electronics / enterprise-computing category;
- elevated route context;
- long dwell interval;
- weekend timing;
- verification pending or gap;
- Exposure Index around 70–85;
- one mitigating condition so the scenario is not purely alarmist.

Example explanation:

> Priority review because high cargo value, an extended weekend dwell window and an unresolved carrier-verification step concentrate during the same route segment. Public aggregate context is elevated for the commodity category, but does not establish shipment-level theft probability.

## Prototype A — Ledger Balance

Most editorial and restrained.

Composition:
- light mineral canvas;
- compact manifest left;
- very large horizontal Risk Corridor center;
- explanation/action right;
- strong typographic rhythm;
- thin ledger rules and route indexing;
- copper used only to reveal concentrated exposure.

Goal: maximum explainability and portfolio sophistication.

## Prototype B — Corridor Focus

Same Freight Ledger identity, but more cinematic.

Composition:
- center Risk Corridor gains more vertical space;
- selected interval receives controlled tonal/depth emphasis;
- queue becomes narrower and more compressed;
- explanation floats adjacent to the exact exposure interval;
- public context remains visibly separate.

Goal: test whether spatial focus makes the mechanism more memorable without drifting into command-center aesthetics.

## Prototype C — Intermodal Ledger

Most modular/experimental version while staying within Freight Ledger.

Composition:
- route segments treated like intermodal/container modules;
- each segment carries time, dwell and exposure marks;
- manifest and corridor share a common grid language;
- reason codes snap visually to the relevant segment;
- action panel resembles a review stamp / dispatch notation.

Goal: test stronger domain recognizability.

## What to compare

Score each prototype on:
- 5-second comprehension;
- 60-second task completion;
- Risk Corridor dominance;
- reason-code explainability;
- freight/logistics recognizability;
- visual originality;
- generic-SaaS risk;
- generic-cyber risk;
- density/readability;
- implementation feasibility in one-day challenge scope.

## Selection rule

Do not choose based only on beauty.

Select the prototype that best supports:

> `Which shipment needs attention, where does exposure concentrate, why, and what should a human reviewer do next?`

## Gate exit

Gate 2.25 passes only when:
- one prototype is explicitly selected;
- the other directions are archived as references;
- layout proportions are sufficiently clear to implement;
- no major product-flow question remains hidden behind aesthetics;
- chosen composition passes the initial uniqueness audit.

After selection, proceed to **Gate 2.5 — Palette / Brand**, followed by **Gate 3 — Design System**. Do not skip directly into effects or animation.
