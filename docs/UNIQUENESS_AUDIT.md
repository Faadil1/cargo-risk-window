# Gate 4.25 — Uniqueness Audit

## Audit question

Could Cargo Risk Window belong to a generic SaaS / AI-security product if its logo and copy were removed?

Current design answer: **sufficiently distinct to proceed**, provided the build preserves the frozen domain mechanisms below.

## Scoring

Scale: 1–5, where 5 is strongest. Generic-AI risk is inverse: 1 is best / lowest risk.

| Dimension | Score | Rationale |
|---|---:|---|
| Domain specificity | 5/5 | Manifest, modal transfer, dwell, route segments and review marks are freight-native. |
| Visual recognizability | 4/5 | Mineral Intermodal + modular route system avoids default BI/security styling. |
| Interaction specificity | 5/5 | Risk Corridor and Manifest Index Transfer exist because of the freight-review job. |
| Explanation specificity | 5/5 | Reason codes anchor directly to route/time/factor contributions. |
| Generic dashboard dependence | 2/5 | Supporting modules remain dashboard-like, but they are subordinate to the corridor. |
| Generic AI/SaaS risk | 1.5/5 | Low if no AI confidence language, glass cards, neon shell or generic hero KPIs are introduced. |

## Audit questions

### Could this belong to 50 other SaaS products?
Not if the selected composition is preserved. The manifest → intermodal corridor → exposure window → review mark structure is domain-specific.

Failure condition: replacing the corridor with a map plus KPI cards would erase this advantage.

### Does the strongest interaction exist because the product needs it?
Yes. The Intermodal Risk Corridor is the main way to see where time, route and exposure concentrate.

### Is the domain visible without reading the pitch?
Target answer: yes.

Required visible nouns/forms:
- shipment / manifest;
- truck / rail / terminal / border / dwell modules;
- route/time progression;
- reason codes;
- human review state.

### Are we translating reference principles or copying a surface?
The intended system translates operational density, exception prioritization and logistics visibility into a new intermodal ledger composition. It must not copy a commercial control-tower shell or map-first layout.

### Is the primary signature merely decorative?
No. Remove the Risk Corridor and the product loses its core analytical job. This is the desired test.

# Generic-risk watchlist

During implementation, reject any change that introduces:
- a generic 4× KPI-card top row;
- a huge circular risk gauge as the hero;
- dark navy command-center shell;
- red alert everywhere;
- glowing/pulsing map pins;
- AI-generated recommendation copy;
- probability/confidence language;
- glass cards;
- generic world map dominating the first viewport;
- unexplained decorative sparklines;
- excessive rounded cards that erase the manifest/container grammar.

---

# Product-specific invariants

At least five of these must remain visually obvious in the implementation:
1. manifest/index structure;
2. intermodal route modules;
3. time + route exposure corridor;
4. critical exposure window;
5. reason codes attached to operational segments;
6. transparent factor contributions;
7. public aggregate context separated from shipment evidence;
8. human Review Mark outcome;
9. Mineral Intermodal canvas/materiality;
10. Archivo + IBM Plex Mono operational typography.

If fewer than five remain obvious at first glance, reopen Gate 4.25.

---

# Build acceptance test

Before Gate 6 QA, capture the first desktop viewport and ask:

> Without the project name, can a reviewer infer that this is a freight/logistics risk-review instrument rather than a generic security dashboard?

Then ask:

> Can the reviewer identify which shipment needs attention, where exposure concentrates and why within roughly 60 seconds?

If either answer is weak, rework composition before adding more effects.
